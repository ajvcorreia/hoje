# Hoje — implementation plan and contracts

This is the source of truth for architecture, the DB schema, the API contract and working conventions.
Changes to contracts go through the orchestrator.

## 1. Architecture decisions

| Area | Decision |
|---|---|
| Realtime | Server-Sent Events + Postgres `LISTEN/NOTIFY` (channel `hoje_changes`). No Redis. The API holds one LISTEN connection and fans out in-process to SSE subscribers filtered by user. |
| Web image | `hoje-web` = Caddy serving the built SPA and reverse-proxying `/api/*` to `api:8000`. `SITE_ADDRESS` env: `:8080` (test, HTTP) or a domain (prod, automatic HTTPS). One Caddyfile (`deploy/Caddyfile`). |
| Concurrency | Integer `version` column on mutable rows; PATCH requires `version`; mismatch → `409` with the current item. `updated_at` is informational. |
| Category colours | Fixed palette of 12 keys (`slate, red, orange, amber, lime, green, teal, cyan, blue, indigo, violet, pink`) with light/dark fill + text tokens meeting WCAG AA. DB stores the key, never hex. |
| OpenAPI | Code-first. `backend/openapi.json` is generated by `python -m hoje.openapi` and committed. CI regenerates and fails on diff. Frontend generates `src/api/schema.d.ts` with `openapi-typescript` and uses `openapi-fetch`. |
| Backend stack | Python 3.13, uv (lockfile committed), FastAPI, SQLAlchemy 2 async + asyncpg, Alembic, pydantic-settings, argon2-cffi, pyotp, segno, cryptography (AES-GCM), zxcvbn, aiosmtplib + Jinja2, structlog (JSON). Ruff for lint+format, pytest + pytest-asyncio + httpx. |
| Frontend stack | React 19 + TypeScript (strict) + Vite, Tailwind CSS v4, TanStack Query, react-router, openapi-fetch, date-fns. ESLint, vitest + Testing Library, Playwright. |
| Rate limiting | `auth_throttle` table in Postgres. |
| Migrations | API entrypoint runs `alembic upgrade head` under a Postgres advisory lock before starting uvicorn. Worker waits for API healthy. |

## 3. Database contract (PostgreSQL 17)

All PKs `uuid` (generated server-side, uuid4), all timestamps `timestamptz`. Extensions: `citext`, `pg_trgm`.

- **users**: id, email citext unique, password_hash text, totp_secret_enc bytea null, totp_pending_enc bytea null, totp_enabled bool default false, totp_last_step bigint null, timezone text default 'UTC', weekend_days smallint[] default '{6,7}' (ISO 1=Mon..7=Sun), last_category_id uuid null (FK categories, set null), created_at, updated_at.
- **sessions**: id text PK (sha256 hex of the raw token), user_id FK cascade, stage text check in ('mfa_pending','active'), csrf_secret text, created_at, last_seen_at, absolute_expires_at, ip inet null, user_agent text null, revoked_at null. Index (user_id).
- **recovery_codes**: id, user_id FK cascade, code_hash text, used_at null, created_at.
- **password_reset_tokens**: id, user_id FK cascade, token_hash text unique, expires_at, used_at null, created_at, requested_ip inet null.
- **auth_throttle**: key text PK, failures int, window_start timestamptz, locked_until timestamptz null, updated_at.
- **categories**: id, user_id FK cascade, name text (1–40), colour text (palette key, check constraint), icon text null, sort_order int, is_leave bool default false, hidden bool default false, version int default 1, created_at, updated_at, deleted_at null. Unique index (user_id, lower(name)) where deleted_at is null.
- **events**: id, user_id FK cascade, category_id FK restrict, title text (1–200), notes text null (≤5000), start_date date, end_date date (inclusive, check ≥ start_date), all_day bool default true, start_time time null, end_time time null, timezone text, repeat text check in ('none','monthly','yearly') default 'none', repeat_until date null, rrule text null (reserved, unused in v1), counts_as_leave bool default false (server-managed from category.is_leave), version int default 1, created_at, updated_at, deleted_at null. Indexes: (user_id, start_date, end_date) where deleted_at is null; GIN (title gin_trgm_ops).
- **reminders**: id, event_id FK cascade, offset_minutes int check ≥ 0, created_at. Unique (event_id, offset_minutes).
- **reminder_deliveries**: id, reminder_id FK cascade, occurrence_date date, due_at timestamptz, status text check in ('pending','sending','sent','failed','skipped'), attempts int default 0, next_attempt_at timestamptz null, last_error text null, sent_at null, created_at, updated_at. **Unique (reminder_id, occurrence_date).** Index (status, next_attempt_at).
- **leave_policies**: id, user_id FK cascade, year int, allowance_days numeric(4,1) default 0, carried_over_days numeric(4,1) default 0, version int, created_at, updated_at. Unique (user_id, year).
- **holiday_calendars**: id, user_id FK cascade, code text ('PT','AE'), name text, enabled bool default false, colour text, created_at, updated_at. Unique (user_id, code).
- **holidays**: id, calendar_id FK cascade, date date, name text, is_non_working bool default true, source text check in ('bundled','user'), estimated bool default false, created_at, updated_at. Index (calendar_id, date).
- **notification_log**: id, user_id FK set null, kind text ('reminder','password_reset','test'), to_address text, subject text, status text ('sent','failed'), error text null, message_id text null, created_at. Never stores tokens or bodies.

Deferred features (RRULE, ICS, audit log, session list, half-days) fit without breaking changes: `rrule` column exists, numeric leave balances allow halves, `sessions` already stores ip/user_agent.

### Domain rules
- Monthly repeat on day 29–31 clamps to the month's last day. Yearly repeat on 29 Feb → 28 Feb in non-leap years. Ranged events repeat with the same length. `repeat_until` inclusive.
- All-day reminders fire at 09:00 in the user's timezone, `offset_minutes` rounded to whole days before the start date (1 day before → 09:00 the previous day). Timed reminders fire at start datetime − offset.
- Vacation: working day = not in `weekend_days` and not an `is_non_working` holiday in an enabled calendar. Counted per calendar year. used = days ≤ today, planned = days > today, remaining = allowance + carried_over − used − planned.
- Reminder delivery: row `sending` committed before SMTP, `sent` after; stale `sending` → `failed` (never resent). Explicit SMTP failures retry at 1, 5, 30, 120 min. Due > 24 h in the past → `skipped`. Claims use `FOR UPDATE SKIP LOCKED`. Deterministic Message-ID `<reminder-{reminder_id}-{occurrence_date}@hoje>`.

## 4. API contract (`/api/v1`)

JSON; errors are RFC 9457 `application/problem+json` (`type, title, status, detail, errors?`). Cookie session auth. Every non-GET request needs header `X-CSRF-Token` and a same-origin `Origin`. Health endpoints live outside the prefix.

```
GET  /healthz                          liveness {status:"ok"}
GET  /readyz                           DB reachable + migrations at head
GET  /api/v1/auth/state                {registration_open, authenticated, stage, csrf_token, user?}
POST /api/v1/auth/register             {email, password} → 201 user (only when registration open)
POST /api/v1/auth/login                {email, password} → {status: "ok"|"mfa_required"}
POST /api/v1/auth/login/mfa            {code} (6-digit TOTP or recovery code)

POST /api/v1/auth/password/forgot      {email} → 202 always
POST /api/v1/auth/password/reset       {token, new_password}

POST /api/v1/auth/2fa/setup            {password} → {otpauth_uri, secret, qr_svg}
```

Core schemas:
- `Category {id, name, colour, icon, sort_order, is_leave, hidden, version}`
- `Event {id, category_id, title, notes, start_date, end_date, all_day, start_time, end_time, timezone, repeat, repeat_until, counts_as_leave, reminders: [{offset_minutes}], version, created_at, updated_at}`
- `EventCreate` = Event minus server fields; `category_id` optional (defaults to user's last_category_id, else first category).
- `Occurrence {event_id, occurrence_start: date, occurrence_end: date, event: Event}`
- `LeaveImpact {year, days, remaining_before, remaining_after, exceeds: bool}` — list, one per affected year.
- `LeaveBalance {year, allowance_days, carried_over_days, used, planned, remaining, bookings: [{event_id, title, start_date, end_date, days}]}`
- `Holiday {id, calendar_id, date, name, is_non_working, source, estimated}`
- SSE: `event: change` / `data: {entity: "event"|"category"|"leave_policy"|"holiday"|"holiday_calendar"|"user", op: "create"|"update"|"delete", id, version}`; `event: ping` every 25 s.

## 5. Security design
- Session cookie `__Host-hoje_session` (httpOnly, Secure, SameSite=Lax, Path=/). Raw token 32 random bytes; DB stores sha256. Idle timeout 7 d, absolute 30 d. Rotate on login completion, password change/reset (revokes all others), 2FA changes.
- CSRF: per-session secret; token returned by `/auth/state`; checked on every unsafe method, plus Origin check against `HOJE_PUBLIC_URL`.
- Throttle: per IP and per account key; progressive lockout (5 failures → 1 min, doubling to 1 h max) on login, MFA, forgot, reset.
- Password policy: min 10 chars, zxcvbn score ≥ 3, max 256 chars.
- TOTP: pyotp, SHA1/6 digits/30 s, ±1 step window, replay blocked via `totp_last_step`. Issuer "Hoje". Secrets AES-GCM encrypted with `HOJE_SECRET_KEY` (32 bytes base64), versioned ciphertext prefix `v1:`.
- Recovery codes: 10 × `xxxxx-xxxxx` (base32), argon2-hashed, single use.
- Reset tokens: 32 bytes url-safe, sha256 stored, 30 min expiry, single use, uniform response and timing.
- Headers (Caddy): CSP `default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'`, HSTS (prod), nosniff, Referrer-Policy same-origin, Permissions-Policy minimal.
- `HOJE_INSECURE_COOKIES=true` (test VM over HTTP) drops `Secure` and the `__Host-` prefix; the API refuses to start with it when `HOJE_ENV=production`.
- Logging redacts keys matching password|token|secret|code|cookie|authorization.

## 7. Working conventions (all agents)

- **The dev machine only writes code.** Never run python/uv/npm/node/docker locally. All verification runs on the test VM through `scripts/vm.sh` (needs `HOJE_VM` and `HOJE_VM_SSH_OPTS` in the environment; the orchestrator supplies them):
  - `bash scripts/vm.sh backend 'uv sync && uv run ruff check . && uv run pytest -q'`
  - `bash scripts/vm.sh frontend 'npm ci && npm run lint && npm run typecheck && npm test'`
  - `bash scripts/vm.sh pull backend/uv.lock` — bring generated files (lockfiles, openapi.json) back to commit them.
- On the VM touch only `~/hoje-test/` and Docker project `hoje-test`.
- Branch per task: `phase-N/<task>`. Conventional commits (`feat:`, `fix:`, `chore:`, `test:`, `docs:`, `ci:`).
- Stay inside the files you own. Do not change contracts in this document; report needed changes instead.
- Never commit secrets, `.env` files, keys or backups.
